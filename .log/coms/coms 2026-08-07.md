- **One CTA style for Message / Showcases / Pricing, with a slanted blue hover fill** → new `components/cta-button.module.css`, adopted by both `SendMessageButton` and `HeroButton`. The nav Message button is the benchmark, so the hero pair shrank from a 51px gradient-framed pill to a 40px one (`h-10`, `rounded-md`, `px-5`, `font-medium`, cream on `--foreground`). #decision
- **The hover fill is a `::before` wipe, not a background transition** — `translateX(-105%) → 0` with a constant `skewX(-10deg)`. Negative angle on purpose: CSS y grows downward, so a negative skew pushes the top edge right of the bottom, which is the direction an italic face leans. Same `--primary` as the h1's italic "money"/"data", which is the effect the request asked it to mimic.
- **The fill bleeds 12px past both ends in fixed px, not %** — a 10deg lean across a 40px height displaces ~7px, so a flush-width fill leaves a triangular gap at one corner. The gap is set by the height (identical on every button), not the width (which differs), so a percentage would be the wrong unit. #decision
- **`isolation: isolate` + `z-index: -1` instead of a wrapper span** — puts the fill above the button's own background but below the label, so no extra markup and no z-index on the text. Verified by freezing the wipe at 30/55/100% against the *compiled* stylesheet: label legible over both halves, corners square at full fill.
- **Yesterday's blue glow kept, scaled down** (`0 0 14px` from `0 0 18px` + `0 0 48px 14px`) — the hero-sized halo was built for a 51px button and reads heavy on a 40px nav one. Same blue as the fill, so the button lights up rather than gaining a second colour. One-line revert either way. #decision
