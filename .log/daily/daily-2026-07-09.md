## Addendum 2 (post-close) — hero CTA animation, built then shelved

- **Built** an animated hero CTA (`hero-cta.tsx` + `hero-cta.module.css`): 14 multicolor lines/bars (indigo `#4f46e5`, orange `#ff991c`, teal `#2dd4bf`, pink `#f472b6` at 0.26–0.55 alpha) grow → hold → collapse inside the "View case studies" pill, reading as a live sparkline behind the label.
  - **Pure CSS keyframes, zero JS, no `Math.random()`.** The page is statically rendered, so runtime randomness would bake into the build or risk a hydration mismatch. A fixed tuple table (`[left, width, height, fill, duration, delay]`) with irregular sizes, mutually non-repeating durations and **negative** delays looks random and costs nothing — bars are mid-cycle at first paint instead of pulsing in unison.
  - Only `transform`/`opacity` animate (compositor-only). `relative isolate overflow-hidden` clips bars to the rounded pill; label is `position: relative` so it paints above the layer without a `z-index`. `@media (prefers-reduced-motion: reduce)` hides the layer — matches the `home-backdrop` / `code-typer` / `nav` convention.
  - Committed by the user as **`bf584b6`**.
- **Reverted the same day, by request.** `page.tsx` is back to the plain `<Link>` — **byte-identical to `e21ded3`**, only a two-line pointer comment differs. The two `hero-cta.*` files stay in the tree, unmounted, with cross-referencing comments so reapply is a one-import swap and nobody deletes them as dead code. An unmounted component's CSS module ships in no chunk, so shelving it costs no bundle bytes.
- **Gotcha worth remembering:** `git checkout -- src/app/page.tsx` did **nothing**, because the animation was already committed. The revert had to be authored as a forward change, not a discard. Verified with `git diff e21ded3 -- src/app/page.tsx` and by grepping the served HTML (`hero-cta-module` count → 0).

Q&A only, no code written. The nav **Message** popup already renders the same `ContactForm` as the Contacts page, posting to the `submitContactForm` Server Action — which already has Zod validation, a honeypot, a 5/hour per-IP rate limit, and the Resend send with `reply-to` set to the visitor. `resend@^6.17.1` is installed.

- **The only missing piece is `RESEND_API_KEY` in Vercel** (Production + Preview) followed by a redeploy. Without it `actions.ts` returns the "email me directly" fallback by design.
- **Trap flagged:** Resend's shared `onboarding@resend.dev` sender only delivers to the address that **owns the Resend account**. `CONTACT_TO_EMAIL` defaults to `vosk.dev@gmail.com` (`siteConfig.contactEmail`), which is *not* the user's `pimp.my.bi@gmail.com` — so the signup email must match the destination, or every visitor sees "sending failed" until `vosk.dev` is domain-verified.
- Also noted: the rate limiter's `hits` Map is per-instance in-memory, so on Vercel it resets on cold start and isn't shared across lambdas. Fine at current traffic; upgrade path is Upstash Ratelimit.
