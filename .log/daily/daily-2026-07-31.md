### Reversal — Preset.io dropped for a self-hosted VPS ✅ (`ADR-0003`)

Asked to investigate whether Preset.io would speed things up. It does — but the pricing
check that `ADR-0001` never ran turned up **Embedded Dashboard Viewer Licenses at $500/month
minimum**, on top of the Professional plan ([preset.io/pricing](https://preset.io/pricing/)).
$6,000/year for a demo on a marketing site, against $12–24/month for a VPS running the same
Apache-2.0 embedding. User called it: **ditch Preset, go VPS.** Applied the same session.

- **`ADR-0003`** written; `ADR-0001` marked superseded rather than deleted. `ADR-0002`
  (one `/work` post per dashboard) unaffected.
- **The site barely moved, which was the point.** The union, route shape, embed component,
  middleware fix, registry filter, i18n and the whole `data/` warehouse are vendor-neutral
  and were untouched. Rewritten: `lib/preset.ts` → **`lib/superset.ts`** (login → CSRF →
  mint, with the CSRF token and its session cookie carried together — Node's `fetch` keeps
  no cookie jar, and sending one without the other fails identically to sending neither).
- SDK `@preset-sdk/embedded` → **`@superset-ui/embedded-sdk`** (same API — the former is a
  fork). Route `/api/preset/…` → **`/api/superset/…`**. Env → `SUPERSET_DOMAIN`,
  `SUPERSET_SVC_*`, `NEXT_PUBLIC_SUPERSET_DOMAIN`. Dropped `referrerPolicy` — self-hosted
  decides framing by CSP `frame-ancestors`, and doesn't read `Referer` at all.
- **`deploy/superset/`** authored: Compose (Superset + Postgres + Redis + Caddy for
  automatic TLS), `superset_config.py` with the four embedding-critical settings marked,
  `init-analytics-db.sql`, `.env.example`.
- **Docs restructured** — `02` was a 500-line paste-ready code dump that now duplicates
  shipped code (`CAND-002`); replaced with `02-implementation-map.md`, a map plus the
  decisions worth not re-litigating. New `03-vps-deployment.md` runbook. `00` and `01`
  rewritten rather than annotated — they had flipped architecture twice in a day and the
  layered "superseded" notes were becoming harder to read than the spec.
- **Supabase left the stack** — it existed only because Preset reaches only publicly
  addressable databases. The warehouse is now an `analytics` database beside Superset's
  metadata Postgres. The SQL itself is unchanged; it was always plain Postgres.
