### VPS purchase spec + handover list ✅ (advisory, late session)

Asked what to buy and what to hand over afterwards. Answered from the shipped stack rather
than generically — the sizing follows from what `deploy/superset/docker-compose.yml` actually
runs (four containers: Superset gunicorn, Postgres 16, Redis, Caddy).

- **Spec:** 2 vCPU / 4 GB floor · **40 GB** disk (the `apache/superset:5.0.0` image alone
  unpacks to ~3–4 GB, and `docker compose pull` needs both image versions resident during an
  upgrade — 20 GB leaves no headroom) · **amd64** over ARM (all four images publish arm64, but
  Superset's arm64 builds get less testing; not worth €0.50/mo) · Ubuntu 24.04 LTS · dedicated
  public IPv4 (billed separately at Hetzner, and Caddy's ACME challenge needs it) · inbound
  22/80/443 only · snapshots on. **Hetzner CX22 ≈ €4.50/mo**, well under the `ADR-0003` band.
- **Handover order — DNS first.** The `bi.vosk.dev` A record has to resolve *before* first
  boot, so it leads the list rather than sitting inside step 2. Then: IP, whether Docker is
  preinstalled (it is not on a plain Ubuntu image), whether the user pastes command blocks or
  grants SSH, and the exact `SUPERSET_FRAME_ANCESTORS` origins — no wildcards are accepted, so
  whether Vercel previews must render embeds is a decision to make now, not later.
- **Secrets stay on the box.** Generated there with `openssl rand -base64 42`, never pasted
  into chat. Flagged the `.env.example` warning: rotating `SUPERSET_SECRET_KEY` later makes
  every stored database-connection password undecryptable. What comes back to me is only the
  service-account *username* and the embed **UUID**; the password goes user → Vercel directly.
