## Two items that were described wrongly

### `metadataBase` — reopened, root-caused, fixed ✅
I closed this at kickoff on a read of `[locale]/layout.tsx:44` and **was wrong**; the build still
warned. It also was not "two routes", as the warning count suggested.

Root cause: `src/app/opengraph-image.tsx` is attached to the **root** segment, which had no layout
and therefore no `metadataBase`. Next resolves metadata top-down, so the locale layout's base always
arrived too late. The image resolves for *every* prerendered route — 36 hits — and `warnOnce`
collapsed that to one line per static-generation worker process. Two workers, two warnings.

Fix: a passthrough `src/app/layout.tsx` that supplies `metadataBase` and nothing else; removed from
the locale layout so there is one source. Warnings 2 → 0. With `NEXT_PUBLIC_SITE_URL=https://vosk.dev`,
canonical, `og:url`, sitemap `<loc>` and the feed self-link all emit the production domain.

### The 404 — there wasn't one ✅
The backlog said "no localized `[locale]/not-found.tsx`". The truth was worse: **that file had never
rendered in production.** `dynamicParams = false` 404s at the routing layer *before* the segment tree
is entered, so the boundary never mounts. Probed live against a production build — all four URL
shapes returned Next's built-in "This page could not be found."

It was also not free: the dead boundary is serialized into every route's RSC payload, which is why
English "Page not found" strings were sitting inside the Russian homepage HTML.

**First attempt, rejected:** reading a proxy-stamped `x-locale` header inside the segment
`not-found.tsx`. It produced correct output — and flipped every `[locale]` route from `●` SSG to
`ƒ` dynamic, because one dynamic API taints the whole loader tree. Caught by diffing build output
against a reverted copy, not by reading. Reverted.

**Adopted (user-approved):** `app/global-not-found.tsx` behind `experimental.globalNotFound`. It
compiles into the separate `/_not-found` entry, so `headers()` there makes only that one route
dynamic. Fonts extracted to `lib/fonts.ts` since the file bypasses the layout and needs its own
`<html>`/`<body>`. The `dict.notFound` keys — present in both catalogues and referenced nowhere since
they were written — are finally load-bearing.
