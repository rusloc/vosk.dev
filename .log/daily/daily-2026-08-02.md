## Session 1 — settings audit ✅

`.claude/settings.json` loads, is valid JSON, has no competing `settings.local.json`, and its syntax
was correct (`Bash(pnpm *)` is valid prefix-wildcard form). Four gaps behind that:

- **The `.env` deny was decorative.** `Read(.env*)` gates only the Read tool, while `Bash(cat *)` and
  `Bash(curl *)` were both allowed — `cat .env` read the secret with no prompt and `curl` could send
  it anywhere. #bug
- **Zero `PowerShell(...)` rules** despite PowerShell being this machine's primary shell, so every PS
  call prompted. `Bash(Select-String *)` and `Bash($env:*)` were PS cmdlets scoped to the Bash tool
  and matched nothing at all. #bug
- **`Bash(git *)` contradicted CLAUDE.md**, pre-authorizing `commit`/`push`/`reset` where the project
  rule is "output git commands, do not execute, do not touch the working tree." #bug
- **Deny prefixes are not semantics** — `rm -rf *` misses `rm -fr`, `rm -r -f`, `Remove-Item -Recurse`.
  Left as-is deliberately; prefix matching cannot express "dangerous."

**My first fix was rejected.** I proposed narrowing — scoped curl, read-only git, a minimal allow
list. The user wanted the opposite emphasis: maximum autonomy for build work. Rewritten to 108 allow
/ 49 deny, with the full toolchain mirrored across **both** `Bash(...)` and `PowerShell(...)`.

Kept denied on purpose: `.env` via every route (Read tool, `cat`, `head`/`tail`, `grep`,
`Get-Content`, `Select-String`); git mutations — which puts the CLAUDE.md rule in the harness rather
than in my memory; `vercel --prod` / `vercel env` / `gh secret` / `npm publish`; recursive deletes
and `sudo`.

**Flagged, not touched:** the user-level `~/.claude/settings.json` is 795 lines of ~450
auto-accumulated YAGA-era rules with no deny block. It unions with the project file so it can only
widen, and it already contains `Bash(git commit *)` / `Bash(git push *)`. Project-level deny still
wins, so the git guard holds. Pruning it is a separate job. #idea

## Session 3 — the SEO pass

Skill `seo-site-optimizer` confirmed accessible (8 reference files). Audited every route with two
parallel Explore agents, then planned and executed.

**The infrastructure was already strong** — central `buildMetadata`, per-locale sitemap with a full
hreflang set, `robots.ts`/`manifest.ts`/OG routes, exactly one `h1` per route, real `notFound()` (no
soft 404s), real dates in `lastmod`. So the work was signal correctness and thinness, not plumbing.

### The find of the day: the home page had no `<title>` ✅

`buildMetadata` passed `title: undefined`, and in Next's Metadata API an explicit-but-*undefined* key
**overrides** the layout's `title.default` instead of inheriting it. The most important page on a
credibility site was shipping title-less.

Invisible in source — `title` was right there in the returned object. Only found by curling the built
output and noticing the `<title>` grep came back empty. #bug

### Containment, not fixes — two deliberate `noindex`es #decision

Both have a named unblocking condition and both are a holding pattern:

- **The RU blog cluster was lying about its language.** `content/blog/*.mdx` is single-language, but
  4 posts + 10 tag pages + the index were statically generated under `/ru` with a Russian canonical
  and `hreflang="ru"` wrapped around English prose. Now `noindex, follow`, hreflang narrowed to `en`,
  English-only in the sitemap. Reachable — the switcher still works. Lifts when translations land.
- **`/work/retail-sales` was indexed while its own body read "This is a placeholder case study."**
  `noindex` flag in `work.ts` + `getIndexableShowcaseSlugs()` for the sitemap. Still routes so the
  showcase grid isn't down to one card. Lifts when the copy is real.

### The fourth blog post existed nowhere a crawler reads #bug

`PAGE_SIZE = 3` with `useState` pagination and no paginated URL **sliced** overflow posts out of the
HTML entirely. Now every card renders and off-page ones are CSS-hidden — same design, same visible
result, all four titles/descriptions/links served. Same fix applied to the showcase list.

### Other fixes

- `/en/*` canonicalization redirect **307 → 308** (temporary told crawlers to keep the prefixed URL).
- `disallow: /api/`; AI crawlers deliberately left allowed.
- **Both conversion CTAs were `<button>`s**, leaving `/contact` reachable from the nav alone. Now an
  `<a href="/contact">` with an intercepted click — dialog as enhancement, link as baseline, modified
  clicks pass through.
- `blogPostingGraph` emitted **English URLs on Russian pages**, contradicting its own canonical.
- Structured data 2 graphs → 7: BreadcrumbList (with a *visible* trail, so markup mirrors content),
  Service + OfferCatalog, ContactPage + ContactPoint, CollectionPage + ItemList, CreativeWork.
- Per-post OG images were orphaned — `buildMetadata` hardcoded the site card, so the per-post route
  was never referenced.
- Three duplicate `abs()` builders collapsed into `absoluteUrl(locale, path)`; the `structured-data`
  one was the buggy third that dropped the locale.
- Optional `updated` frontmatter now feeds `dateModified`, `article:modified_time` and `lastmod`.

**Reverted one of my own changes:** an explicit `robots` on `global-not-found` duplicated the
`noindex` Next already emits there. Caught by grepping the output and seeing two meta robots tags.
