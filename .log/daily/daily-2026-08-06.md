## The nav-highlight request was a much bigger bug 🐞→✅

The ask was "bold Home on the landing page." **No nav item was ever bold, on any page.**

`logicalPath()` refused to strip the *default* locale prefix — deliberately, per its own comment,
because `/en/…` never appears in the browser. But the proxy **rewrites** an unprefixed URL to `/en/…`
*internally*, so a page being prerendered sees `usePathname() === "/en/blog"` and every `isActive`
check failed silently in the static HTML.

The same root cause was emitting **broken language-switch links**: the RU pill pointed at `/ru/en`,
`/ru/en/blog`, `/ru/en/services` — all 404s. It survived because it only exists in prerendered
markup.

**Scope note, checked not assumed:** `metadata.ts` builds its `hreflang` alternates from each page's
logical `path`, never from `logicalPath(pathname)`. The SEO alternates were always correct. This was
a broken *human-facing* link, not a broken signal.

One guard removed. Verified per page after: correct item bold on all six, RU switch now `/ru`,
`/ru/blog`, `/ru/services`.

## Second addendum — the permissions audit (`ecb88c5`, 23:14)

One more request after the addendum above: **fix `.claude/settings.json` so it stops prompting.** Two
causes, both confirmed before anything was changed.

- **Permission rules are prefix matches — only a trailing `*` is a wildcard.** Every rule with an
  interior `*` was dead and had never once matched: `Bash(curl -* http://localhost:*)`,
  `Bash(grep * .env*)`, `PowerShell(Remove-Item * -Recurse*)`. That is why every flagged `curl`
  prompted despite four curl rules sitting in the file. #bug
- **`~/.claude/settings.json` had reached 802 exact-command allow rules / 78 KB**, accumulated from
  clicking "don't ask again" — 43 of them curl variants differing only by URL. Each matches nothing
  but the one command that created it, so the next call prompts again and appends rule 803.

Fixed by granting the `Bash` and `PowerShell` tools wholesale in the project file (13 allow / 49 deny)
and letting the deny list be the guardrail, then pruning the global file **802 → 163 rules, 78 KB → 6
KB**. All 64 non-shell rules preserved; backup at `~/.claude/backups/settings.json.pre-prune-2026-08-06`.
Git writes stay denied, so the CLAUDE.md "output the commands, don't execute" rule is unchanged.

**Named the limitation instead of implying a boundary:** with `Bash` fully granted, the `.env` deny
rules are a speed bump — `node -e`, `python` or `sed` reach `.env` without matching a denied prefix.
What actually holds is `Read(.env*)`/`Read(**/.env*)` on the tool path, verified by having the Read
tool refuse `.env.example`.

**Security finding, not acted on:** three of the pruned rules embedded a Vercel protection-bypass
token in plaintext (`x-vercel-protection-bypass: F2avNW…`, a YAGA preview deploy). Gone from the live
file, still in the backup. **Rotate it** — it sat unencrypted on disk for months. #bug
