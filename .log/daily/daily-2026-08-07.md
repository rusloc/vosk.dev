## The one request — one CTA style, slanted blue hover fill ✅

New `components/cta-button.module.css` is now the single CTA style, used by both `SendMessageButton`
(nav "Message") and `HeroButton` (home "Showcases" / "Pricing"). Message was named the benchmark, so
the hero pair shrank from a 51px gradient-framed pill to Message's 40px one.

The hover fill is a `::before` wipe — `translateX(-105%) → 0` with a constant `skewX(-10deg)` — not a
background transition. The angle is negative on purpose: CSS `y` grows downward, so a negative skew
pushes the top edge right of the bottom, which is the direction an italic face leans. Colour is
`--primary`, the same token as the italic "money"/"data" in the h1, which is the whole point of the
request.

Two details that are judgement, not defaults:

- **The fill bleeds 12px past both ends, in fixed px rather than a percentage.** A 10° lean across a
  40px height displaces ~7px, so a flush-width fill leaves a triangular gap at one corner. The gap is
  set by the *height* — identical on every button — while the widths differ, so a percentage would
  scale the wrong dimension.
- **`isolation: isolate` + `z-index: -1` instead of a wrapper span**, so the fill sits above the
  button's own background but below the label with no extra markup.

## Verification — for the first time, by looking 👁️

Screenshotted the resting state: Message, Showcases and Pricing render identically. Then, because a
static screenshot cannot capture `:hover`, built a test page that links the **compiled** stylesheet
from the running build and freezes the wipe at 30% / 55% / 100% — exercising the shipped rule rather
than a retyped copy of it. That proved three things I would otherwise have had to assert:

1. the label stays legible over both the blue and the dark half, so the `isolation` trick works;
2. the corners are square at full fill, so the 12px bleed is sufficient;
3. the slant leans the same way as the italic "money" photographed directly beneath it.

`pnpm typecheck && pnpm lint && pnpm build` all green; prettier clean.

## A bug caught before it shipped 🐞

**CSS modules are unlayered and beat Tailwind's `@layer utilities`.** The module's
`display: inline-flex` would have overridden `hidden md:inline-flex` on the nav button and left
"Message" visible on mobile, where it is meant to live in the sheet instead. Nav now wraps it in
`<div className="ml-2 hidden md:block">`. This is the kind of defect that ships green and is reported
as a screenshot three days later.
