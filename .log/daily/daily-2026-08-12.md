Two constraints were resolved in code rather than raised as blockers. A square carousel spanning a
full 640–1023px tablet column would be ~850px tall, so the pill row and carousel row are capped at
`max-w-[26rem]` and centered — phones are narrower than the cap, so it exists purely for the tablet
band. And "SUBSCRIPTION" at the eyebrow's `text-xs`/`0.12em` measures ~107px against a 104px third of a
360px phone, so pill type steps down to `text-[10px]`/`0.04em` below `sm`. **English set that floor;
Russian («ПОДПИСКА», 8 chars) was never at risk** — noted because it is the last measurement the RU
locale ever forced, taken five hours after it was retired.

`GROUP_WIDTH` lives in its own `group-width.ts` rather than in `service-groups.tsx`, because that file
is `"use client"` and a server component importing a string from a client module gets a client
reference, not the string. Verified in the emitted output rather than assumed: all four elements carry
`max-w-[26rem] lg:max-w-none` in the prerendered HTML, and Tailwind v4 did generate `max-width:26rem`
from a class literal that only ever appears in a `.ts` file — exactly the shape v4's source scanning
can miss.

## Corrections to my own work

Two errors caught by measurement rather than by luck, both worth keeping because the catching is the
transferable part.

1. **The first pagination fix was wrong and the measurement said so.** Page numbers jumped **140px** on
   page 2. Adding `grow` to the list did nothing — the column is already taller than its
   `lg:min-h-[660px]`, so there is no free space to distribute — and the delta was still −140px. The
   fix that works stacks all pages into one CSS grid cell with non-current pages `invisible`:
   `visibility: hidden`, not `display: none`, because the off-page markup must keep its box, and that
   box is what reserves the height. Measured **0px** at 1440 and 1280. #bug
2. **The showcase page's magic number was invalidated by my own change and I nearly shipped it
   wrong.** The footer's 24px line *was* the language switcher's `py-1` pills; removing them took the
   footer from **89px → 81px**, so `calc(100dvh-9.125rem)` became 8px too small. Re-measured over CDP
   (nav 57 + footer 81 = 138px) and corrected to **8.625rem**. This is precisely the risk the board
   lists as item 11 — "a measured magic number whose comment is the only guard" — realised the same day
   it was written down. #bug
3. **A height budget that under-counted by 60px, caught by arithmetic.** `PageHeader` renders a
   *fragment*, so its intro `<p>` is a sibling of the `<h1>` and a `:scope > *` selector missed it. The
   parts summed to 962 against a measured 1022. **A budget that does not add up to the measured total
   is wrong even when every individual number is right.**

Verification also gained a real upgrade: a **positive control**. The first run reported `/services` —
the designated control — as *not scrolling*, which would have invalidated every "fits" reading beside
it. Squeezing `/services` to 1440×500 gives a page that must scroll; it does, so the probe is proven
able to report overflow. **A control that silently stops controlling is worse than no control.**
