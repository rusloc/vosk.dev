## The lead engine — `lead.vosk.dev` 📋

`docs/bi-lead-engine-spec.md`, 21,492 bytes, user-authored at 20:27. Request: recommend a
minimal-effort subdomain app to run an outbound lead funnel.

**The spec is costed against a stack that does not exist**, and that is the correction that matters.
It states "your **existing** Supabase project" and "you already have Vercel + Supabase Auth wired."
Verified: `package.json` has no `@supabase/*`, no auth, no ORM, and a repo-wide grep for
`supabase|prisma|drizzle|next-auth` returns nothing outside the spec itself. `CLAUDE.md` names Supabase
explicitly in its do-not-add list. **"One migration into an existing project" is therefore a few days,
not a day.** #bug

**Recommended against the spec on three points**, each with a reason:

- **Separate repo and Vercel project, not a route group inside vosk.dev.** The spec puts `/leads` in
  the main app. That couples the portfolio's build and runtime to a private CRM, puts the
  `service_role` key and scraped person-data in the same deployment as a public marketing site, and
  would need an `apps/*` split that `CLAUDE.md` forbids. `bi.vosk.dev` already establishes
  subdomain-per-tool as the pattern. #decision
- **Tier-1 JSON/RSS sources only — which deletes the worker box.** The spec's separate Python process
  on Railway/Fly/VPS exists *only* to serve Playwright crawlers and a Telethon listener. Cut those and
  the entire build fits Vercel + Supabase free tiers with no third host. **This is the single decision
  that makes "minimal effort" true rather than aspirational.** #decision
- **GitHub Actions as the scheduler, not Vercel cron.** Verified: **Hobby caps cron at once per day**,
  timing guaranteed only within the hour, which breaks the batched-enrichment pattern the design needs.
  GH Actions is free and minute-level. Batching N rows per invocation is timeout-proof on any plan and
  idempotent on retry. #decision

Also verified and load-bearing: **Supabase free projects pause after a week without database
activity.** The daily writes keep it alive — a real dependency for a tool checked sporadically, not a
footnote.

Scope cut to 4 tables from 6 (no pgvector; `(source_id, external_id)` + domain catches ~95% of dupes),
`contacts`/`activities` deferred to three columns on `leads`, kanban and Realtime replaced by one
filterable table. **~4–5 focused days, $0/month infra.**
