## The four findings that matter 🔍

**1. ⚠️ Cube Cloud gates embedded dashboards behind Premium — $80/dev/month plus $20 per Viewer seat.**
This was checked first-hand at `cube.dev/pricing` rather than accepted from the research pass, and for a
specific reason: **it is structurally the same trap as `ADR-0001`** — a vendor whose embedding tier was
never priced, reversed by `ADR-0003` over $500/month in Preset viewer licences. It does not bite here,
and both escapes were verified: the gate is on embedding *Cube's own UI*, which this use case does not
want, and **self-hosted Cube Core is Apache 2.0 with no gate**, confirmed at package level. #bug

**2. The JSON REST API is feature-frozen, and this is what changes the design.** Cube's CEO,
2026-05-14: *"we consider [the SQL API] the primary Cube Core API going forward… I'd recommend the SQL
API over our older JSON-based REST API… we're just not adding new capabilities to it."*
`@cubejs-client/core`, `@cubejs-client/react` and `useCubeQuery` all sit on the frozen API. The
recommendation is therefore **the SQL API over HTTP with native `fetch`, and no client library** —
which also keeps `core-js`, `url-search-params-polyfill`, `ramda` and `cross-fetch` out of a
16-dependency app that uses native `fetch` everywhere. #decision

**3. ⚠️ A Cube JWT grants the whole data model by default.** A Superset guest token is scoped to one
dashboard embed UUID; a Cube token is not scoped to anything. **The `/api/superset/guest-token` pattern
does not transfer** — the token must never reach the browser, and the correct shape is a server-side
proxy where the browser names a report instead of sending a query. #bug

**4. The free Cloud tier is worse than its headline, and one decision fixes all of it.** 1,000
queries/day is **account-wide and hard**; deployments **auto-suspend after 30 minutes idle**, so on
sporadic portfolio traffic essentially every visitor eats a cold start; there is no scheduled
pre-aggregation refresh. Caching server-side turns traffic-proportional queries into ~144/day
regardless of visitors, and moves the cold start off the visitor and onto revalidation. #decision

Also recorded, and landing directly on the existing warehouse: **`fact_gl.amount` is `numeric(14,2)`,
and Postgres `numeric` comes back as a JSON string.** `castNumerics` converts it and is documented as
unsafe past `Number.MAX_SAFE_INTEGER`. #bug

## The spike, and a framing error worth recording 🕰️

The plan's next step was a local Docker spike. **The machine has no Docker, no WSL and no Postgres** —
verified rather than assumed. The route around it was found and taken: **Cube publishes the same server
to npm as `@cubejs-backend/server`** (Apache-2.0), and `embedded-postgres` unpacks official PG binaries
into `node_modules` with no admin rights and no service. 684 packages installed;
`scripts/db-server.mjs` written; the seed confirmed to need **no extensions and no superuser** — one
plain `language sql immutable` function over built-in `md5()`.

Postgres was chosen over Cube's in-process DuckDB driver deliberately: `data/*.sql` then runs
**byte-for-byte unchanged**, rather than testing Cube against a hand-ported approximation.

**Then the request was stopped, and the follow-up question was "why do you need docker / PGSQL / WSL??"
— and it was a fair catch.** The day-close message had led with the three absences, which read as a
shopping list of things to install. It was not one; all three had already been routed around before the
message was written. **None of them is needed.** The defect was in the reporting, not the work: *a
message that leads with what is missing reads as a request, whatever it says next.* Same family as this
trail's standing complaint about files asserting things the tree does not support — here it was a
message asserting a blocker the session had already cleared. #bug
