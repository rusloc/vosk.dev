## The five findings that matter 🔍

**1. ⚠️ A constrained enum with no escape hatch does not error — it answers confidently and wrongly.**
`region` offered `KZ / US_CA / EU / AU_NZ / GLOBAL`, so an India-based posting and a US agency were
**both filed as `KZ`** — in the column §3 denormalized *for fast filtering*. A KZ filter would have
returned two leads from neither country. Fixed with `OTHER`; both rows **reset and re-scored rather
than hand-corrected**, so the model chose with the right options instead of me guessing. **The general
risk: every other closed vocabulary in this system has the same failure mode, and it is silent in all
of them.** #bug

**2. ⚠️ `BATCH_SIZE` is bounded by the caller's timeout, and the binding was invisible until measured.**
~9s per posting → a batch of 10 exceeds the 55s `pg_net` window, **severing the connection while the
function completes server-side**: a logged timeout on a run that worked. Same failure class the
phase-1 migration was written to prevent, arriving from the opposite direction. Set to 5. **Any future
job that loops over model calls inherits this constraint.** #bug

**3. ⚠️ Reachability is not usefulness — and its sharper sibling appeared four times: a success code is
not an entity.** `t.me/s/{anything}` returns **200 for channels that do not exist**; Ashby returns 200
with an empty array for unknown slugs; Lever does the same. Then a third variant: **95% parse rate is
not 95% correctness.** HN postings split on `|` 20 times out of 21, but `Data analyst | Chicago, IL`
leads with the **role**, so a splitter writes a `companies` row named "Data analyst" *instead of
erroring*. **Corruption that validates.** #bug

**4. ⚠️ The source catalog was 44% wrong, and twice it was wrong about the source being recommended
next.** Remotive was withdrawn after one probe in the morning; **WeWorkRemotely was named the keyless
fallback at 20:50 and disqualified by one probe an hour later** — 89 items, 0 BI. Written from
documentation, never run. **Probing all sixteen took under an hour; each wrong entry that reached the
build order cost more than that.** #bug

**5. A rejected source was never actually rejected on its merits.** `06-lead-sources.md` specified
Telethon/MTProto and *"a long-running listener process, not a cron job"* for Telegram — infrastructure
§2 of the design explicitly refuses to host, which is why it sat at #7. **`t.me/s/` needs none of it:**
keyless HTTP, 20 posts a page, `?before=` paging verified with zero overlap. It is the **best-yielding
source found** (25% BI, vs ~1% for the ATS sweep) and it was ruled out by a sentence nobody tested.
**An entry can be wrong in a way that rules a source *out*, not just in — and those are invisible,
because nobody probes what the doc already dismissed.** #decision
