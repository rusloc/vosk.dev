## Findings 🔍

**1. ⛔ The abandonment path disables the only alarm that watches enrichment — this is why four days
passed unseen.** `digest` measures a stall as exactly one thing: `raw_postings where processed_at is
null and fetched_at < now()-1h`. `recordFailure()`, on giving up, **sets `processed_at`**. So an
abandoned row *leaves* the backlog and the metric falls back to 0. Verified at the time: stuck metric
**0**, unhealthy sources **0** — the morning message had been printing `✅ 1 source(s) healthy,
nothing stuck` throughout. **And it is worse than silent, it is reassuring: 466 inbox leads have never
been digested, drained 10/day by score, so the digest had ~46 days of runway looking busy while the
engine produced nothing.** #bug

**2. Three more defects in the same function family.** (a) Only `Anthropic.RateLimitError` breaks the
batch; a credit failure is `400 invalid_request_error` and falls through to `recordFailure` — **all
185 abandoned rows hit the 3-attempt cap, none reached that state any other way.** The cap is built
for one poison row and was applied to an account-wide outage, so it ate the whole queue. (b)
`return json({ ok: failed === 0, … })` always returns HTTP 200 — the line of code behind the trail's
"three reads, not one" rule. (c) `enrich` calls no `recordRun`, so it has no `sources` row and never
fires the collectors' Telegram alert; its own comments name (1) as the fallback, and (1) is disabled
by (1). #bug

**3. The engine pays Haiku to re-derive fields the source already publishes.** Himalayas' payload
carries `employmentType` and `locationRestrictions`, and `fetch-himalayas` already runs a BI keyword
regex. So `engagement_fit` (25) + `remote_fit` (20) + `stack_fit` (15) = **60 of 100 score points are
computable in TypeScript with no API call**, and translation is dead weight on an English-language
board. Only the two-sentence summary genuinely wants a model. Four options ranked on §T.5;
recommendation is rules-first scoring plus batched Haiku for summaries — which drops the cost to
roughly nothing *and*, the actual point, **removes the external account from the critical path.**
#decision #idea

**4. A collector alarm that cannot see the one failure it has ever had.** `loadSource()` runs before
`source` is assigned, and the catch reads `if (source) await recordRun(...)`. A failure to load the
source row therefore produces no alert and no `error_count` increment — which is exactly the 09-21
`500`, `source 'himalayas' not loadable: JWT issued at future`. #bug

**5. A git block was handed over and never ran, and only checking caught it.** `a3cf819` landed and
swept up the two files it named; the EOD block never executed, leaving `daily-2026-09-22.md`
untracked and `plan-2026-09-22.md` modified — the whole 09-22 close on disk but not in the repo.
Re-emitted and confirmed landed as `3513002`, verified per-file with `git log -1 -- <path>` rather
than by reading the summary. **"The block was handed over" is not evidence it ran.** #bug

`enabled`, so the connection is alive and the *scope* is gone. Production was verified over plain
