## Findings 🔍

**1. `next/dynamic` in a Server Component page does not split a client component.** A 509 KB
recharts chunk was shipping to the **Power BI** showcase. App Router bundles every client component
a route can reach. It is fixed with a `"use client"` wrapper (`sales-dashboard-lazy.tsx`); a chunk
grep shows **0** recharts chunks on the Power BI page afterwards. **This was measured, not trusted.
The first fix looked right and did nothing.** #bug

**2. recharts 3 turns every chart into an unnamed, focusable `role="application"`.** It is fixed by
forwarding `title`/`desc` through the vendored charts. The combo's `desc` carries every month's
figures, because nothing else gives that chart a text alternative. #bug

**3. The brand palette failed WCAG 1.4.11 as chart marks.** Revenue at `primary`/35% measured
1.76:1, and the brand orange 2.14:1. The owner chose to darken:
- revenue → `primary`/65%, 3.07:1;
- orders line → `amber-600`, 3.19:1, the same hue;
- a white hairline between stacked segments.

The `--color-accent` token added mid-build and orphaned by this was removed again. #decision

**4. The Vercel MCP fault is not what the board says.** T.6.1 reads "the scope is gone".
Re-read today: the connection lists **team YAGA only**, and `list_projects` shows `yaga-web`. The
vosk.dev project is **not visible at all**, so this connection is wired to the wrong team rather
than stripped of rights. The re-auth has to pick the right team. #bug

**5. The cold-start window was open ~3 days (09-24 15:2x → 09-27 15:32) and nobody read it.**
`9e05a57` reset it; the Cube page was rebuilt at 12:50 UTC, so the next window opens **~15:50 on
09-28**. Committing today's rebuild or this close resets it again. T.6.2 (Ignored Build Step) is
still the unblocker. #bug

**6. The 09-23 close was never committed** (`daily-2026-09-24.md`, Finding 1), and there is a
**third tenant in the shared Supabase project** (`daily-2026-09-25.md`, Finding 1). Both were found
by this backfill, neither by the day they happened on.

**7. Every page's canonical URL is a redirect.** The canonical says `https://vosk.dev/...`, which
308s to `https://www.vosk.dev/...`. Search engines then have to resolve a redirect to reach the
canonical. The age of this is unknown; it was found today. #bug
