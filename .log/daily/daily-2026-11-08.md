## Findings

1. #bug **The Mirelo chat eval had never run:** `scripts/chat-eval.ts` used top-level await and tsx compiled it as CJS
   ("Top-level await is currently not supported with the cjs output format"). 11-07's "written, not run" hid a script
   that could not run at all. Fixed by a `main()` wrapper.
2. #decision **The eval passes on the figure, not the tool id.** A right figure reached through a synonym metric
   (Mirelo's loans of returning clients via `repeat_loans`) is a right answer; the ids column shows ⚠ when the expected
   id was not among the calls. All five misses across the three reports (1 + 2 + 2) were right answers the scorer did
   not recognise; no engine or catalogue defect was found by any eval.
3. #decision **P&L data goes to Supabase as JSON columns in chunks of one version × 12 months** (nine per company):
   a whole company is ≈ 10 MB of JSON, more than one Vercel function response may carry (4.5 MB); a chunk is 1–2 MB.
   The engine did not change; `dataset.ts` grew a source seam.

   from the data contract, not from the engine: Python has no data libraries on this machine and `pnl_demo` has no
   rows yet. The lookup tables in `pnl_demo` exist so the same questions can be re-run as SQL once loaded.
