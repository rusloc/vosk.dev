## Findings

1. **#bug The contact form's lead event never reached GA.** `trackLead` pushed `{event:'generate_lead'}` to `dataLayer`,
   which only a classic GTM custom-event trigger reads; nothing in either container did. It now sends a gtag command, which
   the Google tag reads. Fixed in `39cfc18`.
2. **#bug The 11:46 production deploy of `7a8b5a6` (the 11-17 close) failed.** `next/font` could not download IBM Plex Sans
   from Google Fonts during the build: a network failure, not code. Production stayed on `18de8c9` until 12:32, so the
   rewritten blog post was not live for 46 minutes. The 11-17 close did not read the deploy after the push; "pushed" was taken for
   "live". Check the deploy state after every push.
3. **#bug GTM can't publish once a GA4 event tag exists, unless one hidden tag is removed.** Creating the tag makes GTM add
   a `dest_ga` tag and two Google-tag config blocks on its own. With `dest_ga` in the workspace, `create_version` returns a
   bare `compilerError: true` while `quick_preview` passes. Removing it publishes; the script now does that.
4. **#decision Automatic user-provided data collection is on, on the GA side.** The live `gtag/js?id=G-2FXCM9DL8S` carries it:
   hashed email, phone and address from forms, sent to Google. The consent card covers analytics only. Owner to switch it
   off in GA (Admin → Data collection). The GTM copy of that setting doesn't control it.
5. **#decision Container: W5TDFQQJ over PX3R5J8F** (owner, 12:00), for API control; **live now**, the privacy page after.
6. GA batches events that don't change the page: popup clicks (Message, report buttons, Ask AI) arrive 5–10 s late. A probe
   that waits 3.5 s reports them missing.
7. The GTM API quota is low: a 429 after about 15 calls in a minute.
8. `chat_question` was not exercised: it would call the LLM. Same code path as `generate_lead`, which was.
9. Coms stamps: three were estimated and off by a minute (12:16, 12:28, 12:32 → 12:17, 12:29, 12:31), corrected visibly
