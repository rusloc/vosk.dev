## Goal 2 — Full-polish MDX blog + port one article  ·  *the bulk*

### A. Pipeline foundation
1. **Deps:** `next-mdx-remote` (RSC `compileMDX`), `gray-matter`, `rehype-pretty-code` + `shiki`, `remark-gfm`, `rehype-slug`, `rehype-autolink-headings`, `reading-time`. (RSS via a route handler — no extra dep.)
2. **Frontmatter schema** (`src/lib/schema.ts`, Zod `.strict()`): `title`, `description`, `date`, `tags[]`, `cover?`, `draft?`. Fail the build loudly on invalid/unknown fields.
3. **Content seam** (`src/lib/content.ts`): `getPostSlugs()`, `getAllPosts()` (sorted newest-first, drafts hidden in prod), `getPostBySlug()`; reads `content/blog/*.mdx`, parses with gray-matter, validates with Zod, computes reading time. **Pages never touch fs directly.**
4. **MDX components** (`src/components/mdx-components.tsx`): headings, links (`next/link`), images (`next/image`), styled code blocks, lists, blockquote/callout — matching the cream theme + Geist fonts.

### B. Routes
5. **`/blog` list:** cards (title, date, description, tags, reading time), newest first.
6. **`/blog/[slug]`:** `generateStaticParams()` from slugs; `generateMetadata()` per post (title/description/OG/canonical); render MDX with the plugin chain; **prev/next** nav; tags; reading time; back-to-blog link.

### C. Polish (full-polish scope)
7. **RSS** — `src/app/feed.xml/route.ts` generating a valid feed from `getAllPosts()`.
8. **Tags** — render on list + post; **stretch:** `/blog/tag/[tag]` filter pages.
9. **Per-post OG** — static OG via metadata now; **stretch/tomorrow:** dynamic OG images (`next/og` `ImageResponse`, Phase 4).
10. `sitemap.ts` includes blog routes (if a sitemap exists; add blog entries).

### D. Port the article (needs the URL)
11. **Fetch** the old URL (WebFetch) → extract title, body, date, images.
12. **Convert** HTML → MDX; write `content/blog/<slug>.mdx` with validated frontmatter.
13. **Assets** → `public/images/blog/<slug>/…` (⚠ originals may not be fetchable if hotlink-protected — user may need to supply image files).
14. **Proofread** rendering, code highlighting, links, images; fix MDX escaping.
15. `typecheck + lint + build` green; eyeball `/blog`, `/blog/[slug]`, `feed.xml`.

## Goal 4 — GTM → Google Analytics  ·  *small code, external setup + a consent decision*

1. **Inject GTM:** add `@next/third-parties`; render `<GoogleTagManager gtmId={…} />` in the root layout (head script + `<noscript>`). No-op when the id is unset.
2. **Env:** `NEXT_PUBLIC_GTM_ID` (optional) validated in `env.ts`; guard so nothing loads without it.
3. **GA4 inside GTM:** user creates the GA4 property + GTM container in Google's UI and adds the GA4 config tag (All Pages). Code only ships the container.
4. **Conversion events:** `dataLayer.push` on message success (Contacts form **and** nav popup) — e.g. `generate_lead` — so the primary conversion is trackable.
5. **⚠ Consent / GDPR — decision needed (EU audience):** GTM/GA set cookies; EU visitors likely need consent **before** firing + Google **Consent Mode v2**. Options: (a) minimal consent banner gating GTM, (b) Consent Mode default-denied + banner, (c) ship gated behind env and defer consent to a follow-up. **Recommend a minimal consent banner before go-live; do not silently ship untracked-consent GA.**
6. **Verify:** GTM Preview + GA4 Realtime on preview (user-side; needs the container ID).

**Dep:** GTM container ID + GA4 property (user); `NEXT_PUBLIC_GTM_ID` in Vercel; consent decision (Q for user).
