## Goal 1 — Make the contact form actually deliver  ·  **top priority, user-side**

Procedure already written in `docs/contact-setup.md`. Condensed:
1. Sign up at resend.com **with the address that will receive leads**; create an API key.
2. Vercel → Env Vars (**Production + Preview**): `RESEND_API_KEY`.
3. **Redeploy** — env changes don't apply to existing builds.

- ⚠️ **The trap:** Resend's shared `onboarding@resend.dev` sender only delivers to the
  **account-owner's** address. `CONTACT_TO_EMAIL` defaults to `vosk.dev@gmail.com`
  (`siteConfig.contactEmail`), not `pimp.my.bi@gmail.com`. Sign up with the former, or set
  `CONTACT_TO_EMAIL` to whichever address owns the account — otherwise every submit fails silently.
- Verify **on the preview**, per `docs/contact-setup.md`: both entry points succeed, mail lands,
  `reply-to` is the visitor, honeypot sends nothing, 6th submit in an hour is refused.
- **Follow-up (recommended):** verify `vosk.dev` in Resend (SPF + DKIM at GoDaddy), then set
  `CONTACT_FROM_EMAIL="VOSK Website <noreply@vosk.dev>"`. Until then leads arrive
  `From: onboarding@resend.dev`, which reads as a test rig on a credibility site.
