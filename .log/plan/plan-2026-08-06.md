# Plan — 2026-08-06

## Context

pushed, so this is still the first board since 07-21 that is not gated on "commit the batch" or "get

## Priority 1 — Undo the front-page damage · all four items, one change

**Decisions taken 08-06 (user):**

1. **Do all four** — 1A, 1B, 1C, 1D together. Same commit `73eb4dc`, same two files plus the
   dictionary pair.
2. **Keep `ctaSecondary`** ("See services & pricing"). One button on the existing row, not a new
   block, and once the "What I do" links are gone it is the only crawlable path from `/` to the
   money page.
3. **Lede style: one sentence, dry, person-less, service-oriented.** No "I build…" / "I'm a…". Names
   the stack (modern, open-source + SaaS) and the raw-data → decisions move. #decision

### 1A. Delete the "What I do" section

`src/app/[locale]/page.tsx` — the `<section>` holding an `h2` and a three-column `h3` grid, and its
comment. Then the `whatIDo` block from both catalogs (`src/lib/i18n/en.ts`, `src/lib/i18n/ru.ts`).
`ru.ts` is typed `Dictionary` (derived from `en`), so both must move together or the build fails —
which is the correct behaviour.

**Keep:** `h1`, the lede `<p>`, `HomeBackdrop`, `CodeTyper`, both CTAs, `homeGraph()`,
`buildMetadata`. Result: hero + one sentence + two buttons.

**Honest SEO cost — near zero, provided the lede stays:**

| Signal | In the deleted section? | Survives in |
|---|---|---|
| Query terms (Power BI, Superset, DAX, SQL, pipelines) | yes | the lede, `meta.description`, `knowsAbout[]` in `homeGraph()` |
| Links to `/work` `/services` `/blog` | yes | header nav (all five), both hero CTAs |
| A second heading level | yes | **lost — and fine.** A hero page with one `h1` is not a defect |

Do not revert to the pre-08-02 state. A home page of ~8 words was genuinely thin; **revert to hero +
lede**, not to hero alone.

### 1B. Remove the footer nav block

`src/components/footer.tsx` — the `<Container>` wrapping the five-item
`<nav aria-label={dict.footer.sitemap}>`. On a five-page site the header nav already links every page
from every page; a second identical set adds no crawl path Google didn't have, and on a hero-only
home page the duplication is the most visible thing on screen.

Then delete the orphaned `footer.sitemap` key from `en.ts` / `ru.ts` — grep confirms exactly one
consumer. `footer.available` and `footer.rss` stay, as does the copyright / lang-switcher row.

### 1C. Remove tags from the blog **post** page

⚠️ `PostMetaRow` is shared — two callers, confirmed by grep: `blog/[slug]/page.tsx` (tags going) and
`blog/blog-list.tsx` (tags wanted). Add a `showTags?: boolean` prop defaulting to `true`, gate the
existing `tags.length > 0` branch on it, pass `showTags={false}` from the post page only. Do **not**
delete the branch; do **not** touch `blog-list.tsx`.

✅ **Verified safe for SEO:** `/blog` carries an always-visible tag row (`TagLink`,
`blog/page.tsx:57`) added 08-01 *specifically* so tag pages stay reachable on mobile. Every
`/blog/tag/*` keeps an entry point. **Re-grep after editing** — this is the exact class of change
that quietly orphans ten pages.

### 1D. Rewrite the hero lede

The 08-02 copy is three clauses, reads like a CV summary, and restates the `<h1>` instead of
extending it. Replaced per the style decision above. It becomes the **only body copy on the page**,
so it must carry the primary query terms from the 1A table.

### Verify 1A–1D together

`pnpm typecheck && pnpm lint && pnpm build`, then **open the pages in a browser** — `/`, `/ru`,
`/blog`, one post, at desktop **and** mobile width. This is a visual regression and the entire reason
it happened is that 08-02's work was verified by grepping HTML and never looked at. Then re-assert:
`/` still emits `<title>` and `og:image`, `homeGraph()` still renders, `/blog` still links every
`/blog/tag/*`. Confirm on the **Vercel preview deploy**, not just localhost.

  1A–1D and nothing else on those files.

  emergency (it is ugly, not broken) but it is the live first impression on a credibility site.

  blog cluster and `retail-sales` — and both have a named unblocking condition. They are a holding
