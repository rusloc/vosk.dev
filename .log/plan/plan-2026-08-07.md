## Priority 1 — The contact-form env bug · **fourth plan, goes first** #bug

**An empty-string `RESEND_API_KEY` 500s the contact form.** `getContactConfig()` is called at
`contact/actions.ts:67`, ten lines above the `try` at :77. `contact-config.ts:16` types the key
`z.string().min(1).optional()`, so `""` is present-but-invalid and the ZodError escapes the Server
Action.

The bitter part: `contact-config.ts` exists *precisely* so a missing key degrades to "email me
directly" — and that fallback is unreachable in exactly the operator mistake it was built for.

**First recorded 08-01, re-verified as real on 08-06.** It has now appeared on three boards — 08-01,
08-03 (never executed) and 08-06 — and this is the fourth. Small, unblocked, no user input needed,
breaks the site's only conversion path. Every day it has survived, it survived because something more
interesting was asked for. **Do it before reading the rest of this file.**

> The "carried since 07-31" line that rode along from `plan-2026-08-03` through `plan-2026-08-06` was
> wrong — `plan-2026-07-31.md` has no such item. Corrected at the 08-06 close.

Fix shape: move the `getContactConfig()` call inside the `try`, or make the schema tolerate `""` as
"unset" (`.transform(v => v || undefined)`). Prefer the second — it makes the degradation honest at
the source rather than catching a throw. Add the unit test while you are there; the harness exists.

## Priority 3 — The consent banner is English-only · **new 08-06** #bug

`analytics.tsx:58-75` hardcodes the body copy, "Accept", "Decline" and `aria-label="Cookie consent"`.
`<Analytics>` receives only `gtmId` — no `dict` — so a **RU visitor gets an English cookie banner.**

Move the strings into `en.ts`/`ru.ts` under a `consent` key and pass `dict.consent` from
`layout.tsx:86`, which already has `dict` in scope. Small, unblocked, and a real defect on the RU
locale **whether or not GA ever goes live** — do not let it wait on the container.
