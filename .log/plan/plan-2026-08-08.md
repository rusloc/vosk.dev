## Precondition — not a priority

**The contact-form fix is a precondition for this board, not its first item.**

An empty-string `RESEND_API_KEY` 500s the contact form. `getContactConfig()` is called at
`contact/actions.ts:67`, ten lines above the `try` at :77. `contact-config.ts:16` types the key
`z.string().min(1).optional()`, so `""` is present-but-invalid and the ZodError escapes the Server

## Priority 1 — Use the browser. On everything already shipped. #idea

**New, and it goes first because it is a one-time debt payment that gets cheaper the sooner it runs.**

Headless Chrome renders the local build to a PNG:

```bash
pnpm build && npx next start -p 3210 &
# PowerShell — backslash paths, or Chrome writes a file literally named d:tmpshot.png
& "C:\Program Files\Google\Chrome\Application\chrome.exe" --headless --disable-gpu `
  --screenshot="d:\tmp\shot.png" --window-size=1280,900 --hide-scrollbars "http://localhost:3210/"
```

For hover / focus states, link the compiled stylesheet from the running server into a scratch HTML
file and freeze the state with an `!important` override — that exercises the shipped rule rather than
a retyped copy. Pattern proven on the CTA fill, 08-07.

> ⚠️ **`--window-size` does not emulate mobile on this Chrome build, and the recipe above is wrong
> about that.** It ignores `width=device-width`, so `--window-size=390,844` renders the **desktop**
> layout and crops it — no media query fires, no DPR, no mobile user agent. Disproved by shooting
> untouched `/services` at 390px and seeing identical clipping (08-07). **A mobile claim made from a
> `--window-size` screenshot is false.** The mobile leg needs real device emulation — CDP
> `Emulation.setDeviceMetricsOverride` driven over `--remote-debugging-port`, or a newer Chrome with
> working `--window-size` emulation. Until one of those is in hand, shoot desktop widths only and
> **say the mobile viewport is unverified** rather than reporting a cropped desktop shot as mobile.

**Do a full sweep of the six pages** — `/`, `/work`, `/blog`, a post, `/services`, `/contact` — plus
`/ru` and one mobile viewport (390×844, subject to the caveat above). Every "shipped green, still
wrong" entry in this trail traces to this gap: the 08-02 front-page regression, and both 08-06 cleanup
tasks that arrived as user screenshots. **Assume there is more of it sitting there right now.**

**Progress:** `/contact` and `/ru/contact` shot at 1280×900 on 08-07 — and the sweep paid for itself
on its first two pages, catching a grid `align-content: stretch` that spread the Contacts rows ~95px
apart with all four gates green (fix: `content-start` on the `<dl>`). **Four pages plus a post
remain**, and the two done are the two least likely to be broken, because they were just rebuilt.

> **What to actually look for, generalized from that bug:** a grid or flex container that is *itself*

## Carried forward — code items, no user input needed

1. **`.gitattributes` with `* text=auto eol=lf`.** The Edit tool writes CRLF where HEAD is LF — twice

   **happened a fourth time later on 08-07** (`CLAUDE.md`, LF at HEAD → CRLF after one edit). Would
   also settle the two CRLF blog MDX files that fail `prettier --check` at HEAD. **Third board.**
   ⚠️ **Root cause now confirmed, and it is not the Edit tool alone:** `core.autocrlf=true` on this
   checkout with **no `.gitattributes`** — so git hands out CRLF working copies and every write is a
