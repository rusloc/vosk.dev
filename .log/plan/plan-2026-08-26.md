### ⚠️ Vercel Hobby cron is once per day — use GitHub Actions

**Verified 08-25.** Hobby caps cron at one run per day, timing guaranteed only within the hour. That
breaks the batched-enrichment pattern the design depends on. **GitHub Actions cron is free,
minute-level, and just `curl`s the route handlers with a shared secret.** Batching N rows per
invocation is timeout-proof on any plan and idempotent on retry. #decision

```
GH Actions (*/15) ──POST──▶ lead.vosk.dev/api/fetch   → dump JSON into raw_postings
GH Actions (*/10) ──POST──▶ lead.vosk.dev/api/enrich  → N unprocessed → Claude Haiku → upsert leads
                                    ▼
                          Supabase (free) ── RLS ──▶ lead.vosk.dev (one page)
```

**Supabase free tier pauses a project after a week with no database activity** — the daily writes keep
it alive, which is a real dependency and not a footnote for a tool checked sporadically. 500 MB and two
free projects are both far beyond this build.

### Two risks that are not build risks

- **⚠️ Sending from `vosk.dev` threatens the contact form.** The Resend path
  (`CONTACT_FROM_EMAIL`) is the site's only inbound conversion route, and its deliverability rides on
  this domain's reputation. Bulk cold email from the same domain puts spam complaints against the asset
  the whole site exists to feed. **Use a separate sending domain.** The spec is right that sending
  stays manual (`:54`), and for BI contract work **replying to the posting itself has the best reply
  rate and needs no email infrastructure at all.** #decision
- **Person-level data is the GDPR line; company-level is not.** Deferring `contacts` defers the
  exposure too — but spec section 5 (provenance in `source_note`, prune on lost/dead) must come back
  *with* that table, not after it. #idea
